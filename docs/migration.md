# Web 前端渐进迁移

2026-11-03：第一阶段，公开体验站独立运行。

## 当前维护来源

| 范围 | 维护位置 |
| --- | --- |
| 公开版入口、浏览器进度与导入 | piclex-web/apps/public |
| 独立照片/拼写组件及卡组解析 | piclex-web/packages |
| 现有局域网前端和手机服务 | PicLex/local-web 与 PicLex/Services/LocalWeb* |
| 原生 App、签名、设备数据、内置网页产物 | PicLex |

第一阶段从原局域网前端提取拼写规则、照片定位和字符波纹及其测试。文件清单与原指纹在 extracted-files.json。字符波纹颜色改为主题变量；浏览器发音沿用原有先例句后单词的行为。公开版的会话持久化与判题是新增实现，不声称复用了手机 Swift 判题引擎。

旧源码保留作为迁移期的唯一局域网生产来源，当前不接入跨仓库依赖，不修改原生工程和内置网页。共享组件的后续修复需在提取清单记录；第二阶段合并时核对两边自基线以来的差异，不能用这里的旧快照覆盖手机侧的新功能。

## 第二阶段：迁入局域网入口

1. 先盘点当时最新的 local-web，而不是直接使用今天的快照。
2. 将入口、配对、手机管理功能移到 apps/lan；仅导入已适配的共享学习组件。
3. 局域网适配器继续调用手机 API，由手机负责判题、revision、轮次和自动推进；公开版使用自己的本地会话。
4. 分别产出 dist/public 与 dist/lan。公开产物不携带配对、相册或备份入口。
5. 对比既有局域网功能，覆盖断线重连、过期操作拒绝、卡组切换、共享进度、声音与手机管理。未验收前不替换 App 内置包。

## 第三阶段：切换 App 打包

通过局域网回归后，发布固定 Web 版本和产物 SHA-256。PicLex 用明确的版本、接口兼容范围和哈希导入局域网静态包，不在构建时拉取 latest。验证完整 App 基线后按原项目约定构建和交付。稳定切换后移除 PicLex/local-web 的重复源码，保留必要产物和溯源记录。

公开站可以独立发布。局域网前端更新必须与手机接口匹配，并经过 PicLex 的发版核对。
